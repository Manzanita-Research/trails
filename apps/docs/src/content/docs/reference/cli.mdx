The one-command installer is the supported path for normal setup and updates. These commands are available in the installed standalone binary for inspection, recovery, and development.

## Setup

```text
trails setup hub [--name NAME] [--tailscale] [--service svc:NAME]
trails setup join URL [--name NAME]
```

`setup hub` always configures the current Mac as both canonical hub and collector. It installs server, collector, and backup services and performs the initial collection.

With no network flag, setup returns `http://127.0.0.1:7412/`. `--tailscale` additionally configures Tailscale Serve and returns the hub machine's private MagicDNS HTTPS URL. `--service svc:NAME` implies Tailscale and advertises a pre-defined named Service.

`setup join` verifies an existing hub URL, configures this Mac as a spoke collector, performs its initial collection, and installs its collector service. `--tailscale` and `--service` are not valid for join mode.

## Collect

```text
trails collect --once [--server URL] [--device-id ID] [--device-name NAME] [--state PATH]
```

Runs one collection pass and exits. Without overrides it reads the installed collector configuration. The hub uses the same command to collect its own sessions. When Granola is configured, the command runs coding-session collection first and Granola collection second with independent checkpoints; a provider failure returns a nonzero exit without erasing the other provider's successful checkpoint.

## Capture Midjourney generations (experimental)

```text
trails capture midjourney [--job JOB_ID ...] [--project ABSOLUTE_PATH]
  [--since ISO] [--limit 1..50] [--dry-run]
  [--server URL] [--device-id ID] [--device-name NAME] [--state PATH]
```

`--job` is the immediate agent-driven path. It requires `--project`, captures only the named successful generation or variation, and leaves the reconciliation cursor unchanged:

```sh
trails capture midjourney --job JOB_ID --project /absolute/path/to/project
```

Without `--job`, the command repairs history strictly after the saved `(enqueue_time, id)` cursor. The first repair requires a bounded start:

```sh
trails capture midjourney --since 2026-08-03T17:00:00.000Z --limit 50
```

This integration is experimental because Midjourney has no supported public history API. It uses a short-lived isolated `ego-browser` task with the user's existing login, fails closed on authentication or response drift, and stores only validated provider fields plus four offline WebP thumbnails. It never exports cookies, browser storage, authorization headers, account fields, raw responses, or CDN URLs. `--dry-run` uploads nothing, saves no state, and prints only source, count, image, and cursor facts.

The scheduled collector does not run Midjourney capture.

## Serve

```text
trails serve [--db PATH] [--port PORT] [--api-only] [--static-dir PATH]
```

Starts the canonical HTTP service. Installed hubs use port `7412` and always bind to `127.0.0.1`. Optional Tailscale Serve exposure proxies that loopback service; trails does not listen on the LAN.

## Configure

```text
trails configure collector --server URL [--name NAME] [--reset-device-id]
trails configure server --ai-url URL --ai-token-stdin
trails configure granola --created-after ISO [--binary ABSOLUTE_PATH]
trails configure granola --disable
```

Collector configuration sets the canonical hub endpoint and local display name. `--reset-device-id` intentionally creates a new collector identity on the next run.

Server configuration enables the optional authenticated inference relay. The token is read from standard input so it does not appear in shell history or process arguments.

Granola configuration requires an existing collector target and a running Granola Desktop app, but no paid API plan or API key. The default binary is Granola's bundled local Companion CLI at `/Applications/Granola.app/Contents/Resources/bin/granola`; `--binary` supports nonstandard installations. The first pull starts after `--created-after`. Later passes rescan the previous 24 hours so meetings are picked up after Granola finishes their summaries. Changing `--created-after` starts a new source cursor scope, including when the boundary moves earlier.

Trails invokes only local `notes list` and `notes get` commands and never requests `notes transcript get`. It keeps bounded title, generated summary or local note fallback, scheduled time or one creation-time point, and attendee count. The local CLI does not expose folder membership or a canonical note URL, so these captures remain unassigned. Owner and invitee identities, calendar metadata, transcripts, raw command responses, and Granola credentials never enter the hub. Trails does not read Granola's encrypted database or credential files.

`--disable` removes the local collection configuration.

## Back up

```text
trails backup --output PATH [--db PATH]
trails backup --output-dir DIR [--retain 14] [--db PATH]
```

Creates a consistent SQLite backup. Directory mode also prunes committed backups beyond the retention count.

## Install launchd services

```text
trails install server [--dry-run] [--tailscale] [--service svc:NAME]
trails install collector [--dry-run]
```

Writes and loads the launchd jobs used by the current configuration. `--dry-run` prints the planned files and commands without changing launchd.

`--tailscale` and `--service` are server-installation flags. They are rejected for collector installation. Ordinary setup should use `trails setup hub` or `trails setup join` rather than these lower-level commands.

## Version and help

trails version
